1.1.0-beta.3 について / About 1.1.0-beta.3

  • YamaPlayer 1.5.18 と 1.5.19 で使えます（1.5.20 以降は、確認するまで対象にしません）。1.5.19 は、エディターでの確認だけで、実際の VRChat での確認はまだしていません。
    Works with YamaPlayer 1.5.18 and 1.5.19 (1.5.20 or later is not covered until it is checked). 1.5.19 was checked in the editor only, not yet in real VRChat.
  • 改変版の WebUnit Client「DM Modified WebUnit v5.4 (PC)」を同梱しています（YamachanWebUnit の権利者の許可による。パッケージ内の NOTICE.md）。利用者が PersistentMyList の Inspector などで選んだときだけ入れ替えます。公式の Client は退避され、「Restore Official WebUnit」で戻せます。何も選ばなければ公式のまま使います。
    The modified WebUnit Client "DM Modified WebUnit v5.4 (PC)" is bundled (with the permission of the YamachanWebUnit rights holder; see NOTICE.md in the package). It replaces the Client only when the user chooses it (for example in the PersistentMyList Inspector). The official Client is backed up and can be restored with "Restore Official WebUnit". Nothing changes unless you choose it.
  • VCC・ALCOM で YamachanWebUnit を入れ直す・更新すると、改変版は公式の Client に戻ります（このアドオンが Inspector とコンソールで知らせます）。そのときは、もう一度 Install を選んでください。このアドオン自体の更新では、入れ替えた Client は変わりません。
    Reinstalling or updating YamachanWebUnit with VCC / ALCOM puts the official Client back (the add-on says so in the Inspector and the console); choose Install again. Updating this add-on keeps the chosen Client.
  • 実行時のコード・保存データの形式・上限は 1.1.0-beta.2 と同じです。下の既知の制限は 1.1.0-beta.3 にも当てはまります。
    The runtime code, save format and limits are the same as 1.1.0-beta.2; the known limits below also apply to 1.1.0-beta.3.

1.1.0-beta.2・beta.3 の既知の制限 / Known limits of 1.1.0-beta.2 and beta.3

1.1.0-beta.2・beta.3 はプレリリース（ベータ版）です。すべての環境での動作確認は終わっていません。
1.1.0-beta.2 and beta.3 are pre-releases (beta). They have not been tested in every environment.

  • YouTube プレイリストの取り込みは、1 回に最大 100 曲です。100 曲を超えるプレイリストでは、取得できた先頭の 100 曲だけを取り込みます。続きのページは自動では取得しません。ローカルプレイリスト全体の上限は 150 曲です（題名が長いと、それより前に保存容量の上限に達することがあります）。
    One YouTube playlist import takes at most 100 tracks. For a longer playlist, only the first 100 tracks that were received are imported; the following pages are not fetched automatically. All local playlists together hold at most 150 tracks (long titles can reach the storage limit earlier).
  • YouTube のページの形式によっては、取り込めないことがあります。そのときは 1 曲も追加しません（保存済みの曲は変わりません）。
    Depending on the format of the YouTube page, an import can fail. In that case no track is added (saved tracks are kept).
  • YouTube の新しい形式のプレイリストのページで 100 曲を超える場合に、続きの項目がページのどこに置かれるかは確認していません。そのため、先頭の 100 曲が取り込まれても、「最初の 100 曲を取り込みました（続きは取り込んでいません）」の通知が表示されないことがあります。続きのページを自動で取得する機能はありません。
    For playlist pages in YouTube's newer format with more than 100 tracks, where the continuation item is placed on the page has not been confirmed. Because of this, the "first 100 tracks imported (the rest was not imported)" notice may not appear even when the first 100 tracks are imported. There is no feature that fetches the following pages automatically.
  • 100 曲の取り込みでは、数秒の間、一瞬カクつくことがあります。PC 版 VRChat の実際のクライアントでの 1 回の測定で、ページの HTML を読む処理の 1 フレームあたりの最大の処理時間は 5.6 ms、読み終わるまで約 3.5 秒でした。5.6 ms は、描画やほかの処理を含むフレーム全体の時間ではありません。また、1 回の測定の値で、どの環境でもこの性能になることを保証するものではありません。
    Importing 100 tracks can cause a brief stutter for a few seconds. In one measurement in the real PC VRChat client, the longest processing time per frame of the step that reads the page's HTML was 5.6 ms, and reading took about 3.5 s in total. The 5.6 ms is not the time of the whole frame including rendering and other work. It is the value of a single measurement and does not guarantee this performance in every environment.
  • 確認の範囲：PC 版 VRChat のローカルの試験（Build & Test）で、100 曲を超えるプレイリストから先頭 100 曲を取り込めることを確認しました。1.1.0-beta.2 では、次のことをまだ実際の VRChat で確認していません：「最初の 100 曲を取り込みました」の通知の画面表示、取り込んだ曲の再生、再入室や再起動の後の復元。Android／Quest も確認していません。
    Tested: in a local PC VRChat test (Build & Test), the first 100 tracks of a playlist with more than 100 tracks were imported. Not yet confirmed in real VRChat for 1.1.0-beta.2: the on-screen "first 100 tracks imported" notice, playback of imported tracks, and restore after rejoining or restarting. Android / Quest is not tested.
  • 試験の Build では、VRChat SDK のログに Build Finished, Result: Failure が記録されました。ワールドのファイルは作られ、試験用のクライアントは起動しましたが、Build 全体が成功したかは確定しておらず、原因も特定していません。
    In our test builds, the VRChat SDK log recorded Build Finished, Result: Failure. The world file was created and the test client started, but whether the whole build succeeded is not confirmed and the cause is not identified.
  • 試験（1.1.0-beta.1、YamaPlayer は無改変）で VRChat を終了したとき、YamaPlayer の再生位置の取得（GetTime）の処理で Udon の停止が 1 回記録されました。ほかの場面で起きないこと、保存への影響が無いこと、1.1.0-beta.2 での発生の有無は、確認していません。
    In a test (1.1.0-beta.1, unmodified YamaPlayer), one Udon halt in YamaPlayer's playback-time read (GetTime) was logged when VRChat was closed. Whether it can happen in other situations, whether it affects saving, and whether it happens with 1.1.0-beta.2 are not confirmed.

注意 / Notes

  • 更新の前に、プロジェクトのバックアップを取ってください。VCC では、パッケージの取得に失敗すると、入っていた版が消えることがあります。ALCOM を推奨します。
  • Back up your project before updating. In VCC a failed download can remove the installed version; ALCOM is recommended.
  • Unity を開いたまま VCC・ALCOM で更新したときは、Unity に戻って読み込み（Refresh、Ctrl+R）が行われるまで、前の版のコードのまま動きます。Unity を閉じてから更新するか、更新の後に Refresh または Unity の起動し直しをしてください。
  • If you update with VCC / ALCOM while Unity is open, the previous version's code keeps running until Unity refreshes (return to Unity, or Ctrl+R). Close Unity before updating, or refresh / restart Unity after the update.
  • 公開済みの版の ZIP は差し替えません。修正は新しい版で出します。 / A published version is never replaced; fixes come as new versions.
